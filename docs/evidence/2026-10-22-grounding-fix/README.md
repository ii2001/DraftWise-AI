OpenAI는 기존 근거 인덱스만 선택한다. 서버가 JSON·키·개수·정수 타입·범위·중복을 검사한 후 이름·점수·근거를 조립한다. 실패 시 규칙 설명으로 전환한다. 이전 정책으로 저장된 설명도 조회 시 규칙 설명으로 대체하며 DB 원본은 보존한다. 자유로운 전략 답변 범위를 줄이는 선택이다.

## 재현

저장소 루트에서 [최초 증거의 실행 명령](../2026-10-22/README.md#재현)을 사용하되 출력을 `/tmp`로 지정한다. `pytest`는 현재 43개이고 실제 API를 호출하지 않는다. `verify_integration`은 실제 호출 4회, `browser_submission.cjs`는 추가 1회이며 비용이 발생한다. 통합 스크립트는 현재 출력 근거 계약도 검사한다.

이전 이력의 보호·DB 원본 보존은 `tests/test_llm.py::test_old_history_is_sanitized_without_rewriting_saved_data`에서 임시 DB로 재현한다. `legacy-history-check.json`은 기존 분리 DB를 대상으로 한 별도 Chrome 검사 기록으로, 기록의 세션 ID가 있는 DB가 필요하다. 당시 DB는 저장소에 올리지 않았다.

Baseline 시간은 재측정하지 않았다. 점수 계산 코드는 그대로이며 [기존 1,600개 표본](../2026-10-22/benchmark.json)을 사용한다. 실제 API 4건의 이번 HTTP 평균은 약 1.444초지만 모델 지연 감소를 보장하는 통계적 실험은 아니다.

새로운 실제 출력 5개에서 잘못된 밴 서술이 없었고 허용 문장 계약이 성립했다. 원본 수작업 특성의 정확성, 선택 근거의 관련성, 일반적인 의미 정확도·승률·부하·실제 휴대폰·모든 브라우저를 검증한 것은 아니다.
