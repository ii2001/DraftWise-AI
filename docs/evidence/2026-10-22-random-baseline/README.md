## 기준과 재현

- seed `20261022`, 다섯 포지션 각각 2건. 입력마다 중복 없는 밴 10명·아군 4명·상대 5명. 아군과 상대 픽은 해당 포지션 데이터에 맞춰 추첨한다.
- 주력 후보 3명은 밴·픽에 없는 내 포지션 챔피언 중 추첨한다. 양쪽 모두 이 세 후보만 사용한다. 랜덤 Baseline은 균등 선택 1회, 현재 방식은 기존 추천 1순위다.
- 조합 완성도: 최종 아군의 AD·AP·앞라인(`tank >= 2`)·강한 CC(`cc >= 2`)가 각각 하나 이상이면 항목당 25점. MIXED는 AD/AP로 중복 세지 않는다. 같은 수작업 데이터를 쓰는 별도 구조 지표이며 외부 독립 평가가 아니다.
- 원래 100점이던 4개를 보완 성공으로 세지 않았다. 부족했던 6건 중 개선은 2건/4건이다. R06·R08은 모든 후보에 앞라인이 없어 실패했고 그대로 포함했다.
- 앱 추천 점수의 상승은 그 점수로 최댓값을 선택한 결과이므로 독립 정확도 증거가 아니다. 실제 승률·상성·메타 검증이 아니다.
- 준비 20회 후 입력·방식당 200회, 총 4,000개 시간 표본. 순서를 번갈아 실행했다. 결과 선택 RNG와 시간 측정 RNG를 분리해 반복 수를 바꿔도 결과 추첨은 바뀌지 않는다.
- 시간은 로컬 필터링·선택/전체 점수 계산만 포함한다. Baseline과 현재 방식의 작업량이 다르고 HTTP·MCP·LangGraph·OpenAI는 제외한다.
- 최초 측정이 단위 검사 실행과 겹쳐 `attempts/concurrent-tests-*`에 보존했다. 최종 `benchmark.json`은 검사 종료 후 같은 입력·seed·추천 결과로 다시 측정했다.

```bash
.venv/bin/python evaluate.py --cases 10 --seed 20261022 --repeats 200 --output /tmp/draftwise-random-benchmark.json
.venv/bin/python -m pytest -q
node --test tests/test_draft_ui.cjs
```
